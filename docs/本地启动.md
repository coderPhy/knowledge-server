# 本地启动

## 首次启动

需先安装 Node.js、pnpm 和 Docker Desktop，并确保 Docker Desktop 已启动。

```bash
pnpm install
cp -n .env.example .env
docker compose up -d
docker compose ps
pnpm start:dev
```

出现以下日志即表示后端启动成功：

```text
Nest application successfully started
```

> `MEM0_API_KEY` 未配置只会禁用长期记忆，不影响基础功能。

## 使用 pgAdmin 连接 PostgreSQL

Docker 服务启动后，打开 `http://localhost:8088` 并登录 pgAdmin：

- 邮箱：`admin@admin.com`
- 密码：`admin`

右键 **Servers** → **Register** → **Server**。

**常规**页：

- 名称：`Knowledge Hub Local`（自定义，例如 `localhost` 也可）

**连接**页：

| 字段 | 填写 |
| --- | --- |
| 主机名/地址 | `postgres` |
| 端口 | `5432` |
| 维护数据库 | `postgres` |
| 用户名 | `user` |
| 密码 | `123456` |
| 保存密码？ | 按需开启 |

**角色**和**服务**保持空白，其他页保持默认，点击 **保存**。注册成功后展开 **Servers → Knowledge Hub Local → Databases**，就能找到应用数据库 `knowledge_hub`。维护数据库填 `postgres` 是用来建立连接，不是要在应用数据库里填一样的值。

pgAdmin 由 Docker Compose 运行，与 PostgreSQL 共用 Compose 网络，所以主机名填服务名 `postgres`，不要填 `localhost`。

## PostgreSQL 表用途

PostgreSQL 中的 12 张 `kh_` 表分别存放文档信息、账号权限、团队和 AI 对话数据。实体定义位于 `src/**/entities/`，建表及预置数据见 `init-scripts/postgresql/init.sql`。

| 表 | 存储内容 | 项目中的用途 |
| --- | --- | --- |
| `kh_document` | 文档元数据：标题、摘要、状态、作者/团队、标签、计数、发布时间 | 文档列表、编辑、权限检查和发布流程。`content_id` 指向 MongoDB 正文记录的 `_id`；正文不在此表。 |
| `kh_document_review` | 每次提交的审核任务和历史：文档 ID、审核人、结果、意见、时间 | 提审时写入待审记录（`review_result` 为 NULL），审核通过/驳回后填写结果。 |
| `kh_user` | 登录账号、bcrypt 密码哈希、邮箱、头像、状态、最后登录时间 | 注册、登录、用户管理；`deleted` 为逻辑删除。 |
| `kh_role` | 角色名称和唯一角色编码，如 `ROLE_ADMIN` | 定义角色类型，供访问控制使用。 |
| `kh_user_role` | 用户 ID 与角色 ID 的关联 | 一个用户可有多个角色，一个角色也可分配给多个用户。 |
| `kh_permission` | 菜单/按钮/API 权限的名称、编码、父级、路径、HTTP 方法等 | 描述可执行或可见的权限；类型 `1/2/3` 分别表示菜单/按钮/API。 |
| `kh_role_permission` | 角色 ID 与权限 ID 的关联 | 赋予一个角色一组默认权限。 |
| `kh_user_permission` | 用户 ID 与权限 ID 的关联 | 单独给某个用户增加直接权限，不必改整个角色。 |
| `kh_team` | 团队名称、编码、负责人、父团队、状态和排序 | 表示可嵌套的团队结构；`parent_id=0` 代表顶层。 |
| `kh_team_member` | 团队 ID、用户 ID、成员在团队中的身份 | 表示用户属于哪些团队及其身份（如 `leader`/`member`）。 |
| `kh_ai_session` | AI 会话的所属用户、标题、创建/更新时间 | 聊天历史中的会话列表；默认标题可在首次提问后由问题生成。 |
| `kh_ai_message` | 所属会话、发言方（`user`/`assistant`）、消息文本、可选的 JSON 引用来源 | 按轮次持久化 AI 问答，供历史查询和恢复对话使用。 |

关系可以简化理解为：

```text
用户 -> 用户角色 -> 角色 -> 角色权限 -> 权限
用户 -> 用户直接权限 -> 权限
用户 -> 团队成员 -> 团队
用户 -> AI 会话 -> AI 消息
文档元数据（PostgreSQL kh_document）-> content_id -> 正文（MongoDB）
文档 -> 审核历史（kh_document_review）
```

注意：部分 ID 关联由应用代码维护，不一定都在 PostgreSQL 中定义为外键约束。初始化 SQL 会预置 `admin`、`reviewer`、`user` 三个演示账号（密码均为 `123456`）以及基础角色、权限和团队数据。

## 日常启动

```bash
docker compose up -d
pnpm start:dev
```

已在运行的容器无需先停止，`docker compose up -d` 会自动补齐未启动的服务。

## 启动失败时彻底重置

如果出现数据库不存在、初始化脚本未执行或容器持续异常，执行：

```bash
docker compose down
rm -rf ./volumes
docker compose up -d
docker compose ps
pnpm start:dev
```

**警告：** `rm -rf ./volumes` 会永久删除本项目所有本地 Docker 数据，包括 PostgreSQL、MongoDB、Redis、Neo4j 等。重建后 PostgreSQL 会自动创建 `knowledge_hub` 数据库并执行 `init-scripts/postgresql/init.sql`。

如果仍失败，查看容器日志：

```bash
docker compose logs --tail=100
```
